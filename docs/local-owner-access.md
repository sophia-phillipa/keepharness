# Local owner access

Decisions D09, D13 (desktop part) and the D05/D06 groundwork; gauntlet ledger WP-06 (SEC-R5 RC-01, RC-02, RC-04, RC-05).

## Why

Every account on a computer can reach 127.0.0.1. Before this change, the harness gave the owner identity `local` to any loopback request whose Host was `localhost` or `127.0.0.1`, and the admin handed its session cookie to any loopback browser. The harness also honoured the `Tailscale-User-Login` header for any Host, so a page whose name re-resolved to 127.0.0.1 could act under a mapped tailnet login.

## Contracts

| Area | Contract | Code |
| --- | --- | --- |
| Install secret | `<state>/local.key` (default `~/.local/share/keepharness/local.key`), mode 0600, created once and never rewritten. Only its SHA-256 (`local_secret_sha256`) goes into `runtime.json`. | `control/local_access.py`, `control/runtime_config.py` |
| Owner sessions | The secret never leaves the disk. Each sign-in gets a random token (`secrets.token_urlsafe(32)`); `<state>/local-sessions.json` (mode 0600, atomic writes under an exclusive lock) keeps only `{sha256(token): expiry}`, at most 64 sessions (the oldest go first), each valid 30 days. `keepharness open --revoke` empties the list and signs every browser out. A missing or damaged list signs nobody in. | `control/local_access.py` (`issue_session`, `has_session`, `revoke_sessions`), `control/cli.py` |
| Owner cookie | `keepharness-local` (product slug + `-local`) holds the browser's session token: HttpOnly, SameSite=Strict, Path `/`. Cookies ignore the port, so one cookie reaches the admin and the harness on 127.0.0.1; another local port can therefore receive a token, never the install secret, and the owner can revoke it. A cookie that still holds the secret itself (issued before this change) is not a listed session and is refused. | `control/local_access.py` |
| Admin | `GET /` serves the panel to every loopback request, but sets the `admin` cookie only when the owner cookie is a listed, unexpired session. Without it, `/api/*` answers 401 and names `keepharness open`. | `control/routes.py` (`admin_guard`) |
| One-time link | `keepharness open` prints and opens `http://127.0.0.1:<admin port>/open?ticket=<expiry>.<nonce>.<HMAC>`; the admin accepts each ticket once within 5 minutes, issues a new session, sets it as the owner cookie (30 days) with the admin cookie, and redirects to `/`. The secret only signs the ticket. `keepharness` (serve) prints a link only on a terminal, never in a service journal. | `control/cli.py`, `control/routes.py` (`open_link`) |
| Harness `local` | Loopback client, loopback Host, no proxy or Tailscale header, `local_access` on, and a listed owner session when the config carries `local_secret_sha256`; the harness reads the list from `control_state_dir`. The secret is never a cookie or a bearer token. A hand-written config without the digest keeps loopback trust and logs a warning at startup (tests and fixtures only; the admin always writes it). | `ConversationService.identity`, `holds_local_session` |
| Host allow-list | One function, `host_allowed`, for both apps: the admin accepts `127.0.0.1`/`localhost`; the harness's loopback identity accepts the same names; a request with `Tailscale-User-Login` and a Host outside the configured origins gets 403 `host_denied`. Cookies need no Host check, because a browser never sends 127.0.0.1's cookies to another name, and a rebinding page cannot know a bearer token. | `control/local_access.py`, `ConversationService.identity` |
| Tailscale login | Mapped only when the request looks like Tailscale Serve's proxy hop: Host equals the netloc of `browser_url`, `X-Forwarded-Host` equals Host, and `X-Forwarded-For` is one tailnet address (100.64.0.0/10 or fd7a:115c:a1e0::/48). Serve sets both headers and strips client-sent identity headers (tailscale `ipn/ipnlocal/serve.go`). Without `browser_url`, or when its host is a loopback name or address, the header is never honoured. Another account on this computer can send the same headers to 127.0.0.1, so the connecting socket must also be tailscaled's: every `/proc/net/tcp` row for the connection (client port to harness port) must be ESTABLISHED, owned by uid 0 and have a socket inode (a closed connection is re-labelled uid 0, inode 0 whoever opened it). Uid 65534 is never accepted: inside a user namespace host uid 0 is unmapped and every unmapped account shows as 65534, so tailnet sign-in is off there (the admin status says so and the harness logs it at startup); run KeepHarness on the host. A refused proof logs one line a minute. A request with `Tailscale-Funnel-Request` gets 403 `funnel_denied` on both services. | `ConversationService.through_tailnet_serve` |
| Tokens | A bearer header or `harness_token` cookie names a client only on a direct loopback connection: loopback peer, no `X-Forwarded-For`, no `Tailscale-*` header. The local MCP bridge qualifies; a Tailscale Serve forward (loopback peer with `Tailscale-*` headers) does not, so a token never stands in for a tailnet identity. There is no shared VPN key. |
| Project folders | `POST`/`PATCH /v1/projects`, `DELETE /v1/project-folder` and `GET /v1/project-directories` answer 403 `project_management_local_only` to anyone but `local`, before any other check. | `agent_service/routes/projects.py` |
| Service control | `POST /v1/services` with `start`, `stop` or `restart` needs an enrolled approval session and then the `local` identity; anyone else gets 403 `service_control_denied`. `list` is unchanged. | `agent_service/routes/projects.py` (`services`) |
| Sharing | `project_registration` (admin default true) enables registration. `shared_projects` (top-level boolean in the admin settings, default false, like `personal_setup` and `full_access`; no switch in the admin panel yet) decides whether clients other than `local` (the VPN key and tailnet logins) receive the projects; providers and `local` always do. Those clients start with `sem-projeto` only. | `ProjectService.share_projects` |
| Guest views | For clients other than `local`: `GET /v1/harness-agents` returns only name, backend, model, effort and availability; `/v1/resources` and `/v1/catalog` replace every absolute `source` path with the item's logical `resource_id`. | `harness_agents.public_view`, `resources.without_host_paths` |
| Enrollment refusal | The 403 `approval_session_required` body adds `login` for a tailnet identity. The UI tells `local` to run `keepharness approve-device --owner local`, and tells anyone else to ask the owner of this KeepHarness to run it with their login. | `approval_sessions.require_approval_session`, `ui.js` (`enrollmentMessage`) |
| Desktop | The main process reads `local.key`, signs a one-time `/open` ticket with it, redeems the ticket at the admin and copies only the returned session cookie into the window; the secret never reaches the renderer. App origins (navigation, clipboard write, notifications) are `127.0.0.1` only, not `localhost` (RC-13). When the harness window has no `harness_session` cookie, it runs `python -m control approve-device --owner local --yes`, loads the printed link only if it is an `/approve-device` link on the window's harness origin, and submits the confirmation form. | `desktop/main.cjs`, `desktop/policy.cjs` |

## Failure modes

- A missing or unreadable key in the desktop, or an admin that does not redeem the ticket: no cookie is set, so the window gets 401 from both apps; `keepharness open` still works.
- A browser signed in before this change holds the raw secret as its cookie: both apps refuse it and the admin's 401 names `keepharness open`; opening a new link replaces the cookie. Each desktop start mints a new session; old ones expire or fall off the 64-entry list.
- A failed or slow enrollment command (20 s limit) or a link on the tailnet origin: the window opens normally, and approvals show the enrollment message.
- An admin restart within a ticket's 5 minutes forgets the used tickets, so such a ticket could be replayed once until it expires.
- The owner cookie, like any cookie on 127.0.0.1, also reaches other local ports from same-site pages. SameSite=Strict keeps it out of cross-site requests; a leaked token is revocable and expires, unlike the secret.

## Not in this change

The owner "Enroll a device" button and the list of enrolled devices with Revoke (D13 B/C), Owner/Guest roles (D05), a panel switch for `shared_projects`, and redaction of project roots in `GET /v1/projects` and `GET /v1/project-folder`.
