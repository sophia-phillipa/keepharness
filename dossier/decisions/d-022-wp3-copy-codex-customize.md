# D-022 — WP3 copies Codex Customize without a mockup step

Status: accepted. Date: 2026-10-05 (window 6). Decided by: Sophia. Spec: [WP3](../codex-parity-design.md#wp3-customize-screen-l-admin-frontend--small-python).

## Context

The design planned 2–3 mockups for Sophia before building WP3, per the house rule for layout changes.

## Decision

No mockup step. WP3 copies the Codex Customize and Settings › Plugins screens as closely as possible: layout, chips (Plugins | Apps | MCPs | Skills), Add menu, per-row switches, card and detail view, wording and spacing from the [Codex app inventory](../research/codex-app-inventory-2026-10.md). Provider badges and the "Providers" block ([D-019](d-019-parity-product-answers.md), Q3) are the only KeepHarness additions. Colors follow [D-020](d-020-theme-tokens-for-copied-screens.md).

## Rationale

The target is already fixed by the Codex screens; mockups would only re-ask an answered question. Sophia's words: "inspire 500% in Codex".

## Alternatives

Mockups first: rejected as redundant.

## Impact

WP3 goes straight to implementation once WP2 and WP4's family key exist.
