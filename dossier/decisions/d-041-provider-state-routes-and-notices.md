# D-041 — Provider-state routes, switches and external-change notices (W10 Track A)

Status: accepted. Date: 2026-10-08. Decided by: W10 orchestration session (Sophia's standing W10 instruction), reviewed by Opus architect. Builds on [D-038](d-038-keepharness-facade-over-provider-state.md) and [D-039](d-039-single-owner-facade-policies.md). Closes the spec gaps of #21 (Plugins row switches write the CLI's real state) and #43 (announce provider-state changes made outside KeepHarness). Design: [provider facade design](../provider-facade-design.md) §2.3-2.4, Contracts (HTTP), F10, F12, F14. Items marked "revisit with Sophia" are product-taste defaults chosen closest to the existing UI and D-039 item 8; the design document is not edited.

## Context

The adapters of #39/#40 (`adapters/codex/state.py`, `adapters/claude/state.py`) are finished but built nowhere in `control/` or `agent_service/`, keep no last-seen map, and raise `HarnessError` subclasses that `control/routes.py` `endpoint` does not map (it catches only `APIError` and wraps every handler result in `JSONResponse`). The design names the HTTP contract and failure modes but leaves twelve gaps: who owns the seen map, the 409 body, the "No project" root, the row source, the notice schema, the harness-versus-control writer, the coalescing key, the admin lock, notice placement, the revert detector's scope, the wizard guard and version drift. The scope fence keeps out #22/#23 (Apps/MCP/Skills chips), #44 (trust, `.mcp.json` approval), #45 (runs on real homes) and DeepSeek (#33/#47).

## Decision

1. **Seen-map owner (F12).** The control process owns it: a new `control/provider_state.py` `ProviderStateService` wraps `adapter.set_enabled` and updates `<state>/provider-state-seen.json` under the same per-provider lock after a successful write. The adapters stay unchanged. The F12 update first diffs the post-write snapshot against the seen map excluding the written item, so an unrelated external change landing in that window still becomes a notice.
2. **409 body.** `409 {"error": "provider_state_conflict", "snapshot": {...}, "external_changes": [...]}`: the control envelope plus the fresh snapshot, produced by one fresh read (coalescing bypassed). `endpoint` gains a pass-through: a handler may return a Starlette `Response`, returned as is; all provider-state error mapping lives in `control/provider_state.py`, not in a generic `except HarnessError` (which would change other routes).
3. **`sem-projeto`.** `project_root=None`: user layers only. No-project runs use per-conversation workspace folders (`conversation_service.py:677`), so there is no stable folder to key Claude MCP on; the adapter already shows Claude MCP rows with its "choose a project" reason. Track A pages call with `project_id=sem-projeto` (customize.js has no project selector).
4. **Row source** (JEV: `union`, confidence 0.83). The integration catalog stays the row list, merged by id across CLIs. Each provider pill on a row gets its own switch only when that provider's snapshot has a `StateItem` with the same id; catalog-only items show "Not installed in <CLI>" and no switch; snapshot-only plugin items are appended as rows so nothing the CLI loads is hidden. The switch writes the item's own `scope` (the deciding layer), no scope picker. **Revisit with Sophia:** a scope picker, and one switch per provider versus one per row.
5. **Notice schema.** One file, keyed by `"<provider>|<project_id>"`, holding the stat fingerprint, last-seen `{enabled, source}` per item, the last KeepHarness write per item, and pending notices. A notice is `{id, item_id, name, change, before, after, source, detected_at}` (a superset of the design's `{item_id, before, after, source, detected_at}`); `change` is `changed | added | removed | reverted`; `before` and `after` are booleans or `null` for absent; `id` is `n_` plus 16 hex digits of a sha256 over provider, project, item, before, after and detected_at. One pending notice per item: a newer change replaces it, keeping the original `before`, and it is dropped if the item came back to that value. The first read of a key records a baseline and announces nothing. At most 50 pending notices per key.
6. **Run start** (JEV: `A`, confidence 0.97). The harness only stats: `queue_worker.run_job` calls `control.provider_state.run_start_check` (stat of `watch_paths`, no parse). When the stat differs from the seen map's, it records `{stat, detected_at}` in a second file, `<control_state>/provider-state-runs.json`, written only by the harness. The control process diffs on the next GET and uses that earlier `detected_at`. One writer per file, no file lock, no change to how runs are built, and `conversation_service.py` untouched.
7. **Coalescing.** One `asyncio.Lock` per provider (CLI calls to one provider never overlap), a 5 s cache per `(provider, project_id)` holding the snapshot and its time. A successful POST replaces that cache entry with the post-write snapshot (a stale cached fingerprint would cause a needless 409). Pending notices are always taken from the in-memory seen map, never from the cache, so an ack shows at once. The harness keeps its own 5 s per-key memory.
8. **Admin lock** (JEV: `keep`, confidence 0.85). `POST /api/provider-state` and `notices:ack` stay under `manager.lock` (other admin POSTs get the usual 429 during a write of a few seconds); the per-provider lock nests inside it. GET takes only the per-provider lock. The UI already serializes writes through `action()`.
9. **Placement.** Plugins page: a notice block at the top of `#plugins-panel`. Settings › Providers: a new `#provider-state-notices` container at the top of `#dashboard`, above `#configured-providers`. A toast fires only from those two screens, once per notice id per page session (an in-memory set; no new `localStorage` key). Refresh happens on screen entry and on `focus`/`visibilitychange` while one of them is open; no timers. "Dismiss" acks the shown ids. **Revisit with Sophia:** placement, the toast-on-other-panels choice, and the wording.
10. **Revert detector (F14) scope.** Generic for every item KeepHarness wrote, both providers: if a later diff finds the item back at the value it had before KeepHarness's last write, the notice is `change: "reverted"`, shown as "Reverted by Claude Code" (or "by Codex"). The cost is a `writes` entry per touched item, cleared at the next detected change.
11. **Wizard-edit guard.** Dropped: `POST /api/provider-state` never writes `settings.json`, so it cannot clobber unsaved wizard edits.
12. **Version drift.** The adapter stays the only judge: rows are not pre-disabled; a 422 `provider_state_version_untested` shows its message in the row note and the switch stays at the server value. For Track A it is mostly moot: plugin writes go through CLI commands, which are allowed outside `tested_versions`; direct edits (skills, MCP) belong to #22/#23.

## Rationale

Every gap is closed in the control service or the UI, with the adapters of #39/#40 unchanged and no new process, store or timer. The seen map has exactly one writer per file, which removes the cross-process race without a file lock. Keeping the admin lock and returning a `Response` through `endpoint` are the two smallest edits to `control/routes.py`. The F12 self-diff and the cache refresh after POST answer the two races the scenario band found: an external change swallowed by the KeepHarness write, and a stale cached fingerprint. Credentials stay out: bodies carry snapshot fields (ids, names, flags, source labels) and adapter-authored messages capped at 300 characters; logs carry error codes only.

## Alternatives

- Seen map inside the adapters (literal F12): rejected; it reopens finished, reviewed modules for state that belongs to the KeepHarness UI.
- Generic `except HarnessError` in `endpoint`: rejected; it would change how other harness errors reach the admin panel.
- Harness writes notices into the seen file under `fcntl.flock` (B), or a run-start no-op (C): rejected by the JEV and on the merits (two writers, or the acceptance item unmet).
- Bypass `manager.lock` for these routes: rejected; more code in `endpoint` for a single-owner panel whose UI serializes anyway.
- Snapshot-only or catalog-only row list: rejected; one hides not-installed catalog items, the other hides what the CLI really loads (D-038).
- A periodic watcher: rejected by F10.
