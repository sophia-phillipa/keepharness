# D-043 — DeepSeek uses the Codex engine for 1.0; qualify dsh separately

Status: accepted for the 1.0 implementation plan. Date: 2026-10-08. Decided by: the W13/W14 design session under Sophia's instruction to resolve design gaps with JEV and independent review. Builds on [D-038](d-038-keepharness-facade-over-provider-state.md) and [D-039](d-039-single-owner-facade-policies.md) item 10. Design: [provider facade](../provider-facade-design.md) §2.7. Research: [DeepSeek CLI](../research/deepseek-cli-2026-10.md). Issues: #33 and #47. Release notes: the future 1.0 release record must cite this decision and actual implementation validation; it has not been written by this design task.

## Context

DeepSeek already runs through Codex's app-server with `model_provider="tail_api"`, Responses HTTP, `requires_openai_auth=false`, a separate home and a private API key. It retains local Codex history through `native-thread.json`; `context_strategy=client_history_replay` does not describe a DeepSeek-hosted conversation. See [backend.py](../../adapters/deepseek/backend.py), [account.py](../../adapters/deepseek/account.py) and the [adapter specification](../../adapters/deepseek/specs/README.md). The checked-in compatibility record names Codex `0.155.0-alpha.9.2`; the specification records later `0.157.1` adjustments. Neither is a new 1.0 validation result.

D-038 asks for an autonomous DeepSeek engine. D-039 explicitly keeps the existing engine until a spike proves DeepSeek Harness (`dsh`). This record settles the 1.0 boundary without treating upstream documentation as a tested KeepHarness integration.

## Decision

1. **Keep Codex as the supported DeepSeek engine for 1.0.** Complete #47's isolation and facade work. D-038's `dsh` direction remains the target, with qualification separate from the release blocker. Do not install or select `dsh` automatically.
2. **The seam is an extension point, not a second harness.** Reuse `ProviderStateAdapter` and `run_native`. The shared types already contain `engine`, `hook`, `instructions` and `profile`; #47 must wire and test their consumers rather than introduce duplicate types. A future `dsh` adapter owns its native state and protocol mapping. No generic YAML engine or extra provider registry is required by 1.0.
3. **Engine identity is explicit.** DeepSeek snapshots and newly written session metadata identify provider `deepseek`, engine `codex`. A legacy marker known from the existing DeepSeek session/configuration context may resolve to that same pair and be enriched on its next normal write; this is not a bulk state migration. Explicit engine/provider mismatch or ambiguous provenance refuses resume. No Codex id is sent to `dsh`, and no failure silently changes engine.
4. **`dsh` follows qualification, behind an off-by-default experimental flag.** There is no enabled or selectable `dsh` runtime in 1.0 under this decision. A later adapter must pin the tested package version, hard-fail with `provider_version_unsupported` outside its tested set, and preserve the chosen engine on failure. The flag is introduced with that adapter, not as an empty 1.0 setting. Any default switch needs a new decision with runtime evidence.

## What 1.0 ships

- DeepSeek inference and balance/account checks keep their current API-key path. Key storage stays mode 0600 and never appears in arguments, logs or model-shell environments.
- DeepSeek's Codex engine uses `<state>/providers/deepseek` as its `CODEX_HOME`, never the owner's ChatGPT home. Plugins, skills and MCP rows read/write this engine's state through the Codex adapter bound to that home. User orchestration is this separate home; project orchestration still follows the provider facade's trust and project rules.
- Before either attended or scheduled execution, #47 checks credential isolation, rejects forbidden `auth.json`/matching keyring state with `deepseek_credential_isolation`, selects file credential storage and explicitly removes the DeepSeek key from model child-shell environments. Detection failure must not count as a clean check; it refuses the run without deleting credentials. The version-tested Codex setting and keyring lookup belong to #47 acceptance, not an assumed filter syntax.
- Existing permission semantics follow the facade and [D-044](d-044-scoped-sandbox-under-facade.md). The Codex-backed DeepSeek route does not preserve a separate copy-based `scoped` exception. Native engine permissions and the owner-only access gate remain authoritative.
- Engine-tagged continuation retains the existing `native-thread.json` marker and ordinary Codex history behavior. A mismatch reports the condition and requires an explicit new native session; it never performs a cross-engine resume or conversion.

## Rationale and alternatives

| Candidate | Consequence | Disposition |
|---|---|---|
| A — Codex for 1.0 plus #47; qualify `dsh` later behind a flag | Delays full autonomy but retains the existing tested transport while closing current isolation gaps. Unknown `dsh` details cannot block or silently enter 1.0. | Selected. |
| B — Switch the 1.0 default to `dsh` now | Requires new credentials, state writes, approvals, session continuation and event mapping on a preview contract with unresolved runtime evidence. | Rejected for 1.0. |
| C — Another engine or a custom API harness | Adds another integration or reimplements the tool/session harness without evidence that it meets the autonomy and facade contracts better. | Rejected for this scope; no third-party alternative was certified by this review. |

JEV consultation on 2026-10-08: `request_decision`, medium risk, candidates A/B/C, selected **A**, confidence **0.92**, threshold **0.80**, accepted; one gateway call. Evidence included the existing adapter, D-039/§2.7, official preview/release facts and the untested authentication/state/session contracts. JEV advised the scope choice; it neither validates upstream facts nor authorizes runtime changes. There was no unresolved JEV result for this choice. Future abstention or gateway failure leaves the existing engine and the experimental flag disabled as the safe reversible local choice, recorded as **revisit with Sophia** rather than inferred approval to switch.
