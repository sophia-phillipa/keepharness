# D-044 — Scoped sandbox under the provider facade

Status: accepted for implementation; not implemented by this record. Date: 2026-10-08. Decided by: the W13/W14 design session under Sophia's instruction to settle #34, with JEV consultation and independent review. Builds on [D-038](d-038-keepharness-facade-over-provider-state.md) and [D-039](d-039-single-owner-facade-policies.md). Design: [provider facade](../provider-facade-design.md#21-runs-on-the-real-homes). Release notes: the implementing release must record this change; no 1.0 release is claimed here.

## Context

D-038 makes scoped isolation desirable, not required, and places it last in the milestone. It also requires provider runs to load the CLI's real orchestration. #45 removes the 0.15 homes and credential-file overrides. The existing cloud scoped transport cannot satisfy both contracts by changing a path.

Evidence at repository commit `3a0cd4a`:

| Source | Current behavior and implication |
| --- | --- |
| `adapters/shared/scoped.py:prepare_scoped` | Reads `config.auth_file`, copies it into a private home (persistent when `session_dir` exists), writes its own `config.toml`, and binds that home writable in bubblewrap. It exposes selected source roots read-only and stages proposals through `selected_project` MCP. It shares the host network (`--share-net`); it is not a network isolation guarantee. |
| `adapters/codex/scoped.py:run` | Disables shell tools, apps, multi-agent and web search, uses only the constructed MCP setup, and resumes `remote-thread.json` inside the private home. |
| `adapters/claude/scoped.py:run` | Uses an empty built-in tool set, strict MCP configuration, no setting sources, disabled hooks and `--no-session-persistence`; history is replayed by KeepHarness. |
| `control/runtime_config.py:build_cli_provider` | Supplies credentials from `<state>/providers/home/.codex` or `.claude`. #45 retires this source. |
| `agent_service/config.py:EXECUTION_MODES`, `ConversationService.bind_execution_mode` | Codex/Claude offer native and scoped; the mode is fixed at conversation creation. DeepSeek/Gemini offer native only. Local offers scoped only. |
| `ConversationService.configured_execution_mode`, `agent_service/ui.js:supportedExecutionModes` | Old conversations can derive a mode from service configuration; the UI also has a hard-coded Codex/Claude fallback. Both require an explicit retirement policy to avoid silent native execution. |
| `adapters/local/sandbox.py:wrap` | Local inference has a separate filesystem boundary. It does not use `prepare_scoped` to copy a cloud login. The common word `scoped` does not make these the same transport. |

Execution mode and permission preset are separate today. `ask`, `read_only`, `auto` and `full` are access presets (`agent_service/approval_policy.py`); native Codex builds sandbox/approval policies, and native Claude builds permission flags. Removing the additional cloud transport does not remove these presets. #45 owns their D-039 correction, including removal of orchestration filtering and the scheduled-run clamps. A native permission mode is not a promise of the retired bubblewrap boundary.

## Decision

**Recommendation: retire the Codex and Claude scoped execution routes from the supported 1.0 surface; keep their native CLI permission modes. Preserve Local's independent scoped isolation.** This settles #34 for 1.0 without introducing a credential broker, replicated configuration or a second source of truth.

**What 1.0 ships:** Codex and Claude use `native` on their real CLI homes with #45's permission presets and #44's trust/MCP rules; DeepSeek uses the route in [D-043](d-043-deepseek-engine.md); Local continues to use its existing `scoped` sandbox. Codex/Claude scoped execution is unavailable, including through API, schedules and workflow stages. There is no cloud-scoped feature flag in 1.0.

1. **Capabilities and dispatch.** Advertise only `native` for Codex/Claude in the authoritative execution-mode contract and every model/resource/effect capability derived from it. Keep DeepSeek/Gemini native-only and Local scoped-only. Remove Codex/Claude registration and imports of the scoped executors; an internal direct dispatch cannot still reach `prepare_scoped`. Shared code is deleted only after checking its consumers; retain helpers required by Local or other live features.
2. **Reject before executing.** An explicit Codex/Claude `execution_mode=scoped` gets the existing HTTP 422 `execution_mode_unsupported`. Validate requests before enqueueing; repeat the guard at worker dispatch for jobs queued before upgrade and workflow/schedule-generated jobs. A rejected queued job ends with that error without a provider spawn, login read, credential copy or proposal application. Admission failure never chooses native as a fallback. Unsupported schedule creation/update is rejected; an already stored schedule occurrence records the failure through the existing scheduler/job error surface, with no automatic rewrite to native.
3. **Stored conversations remain readable, never reinterpreted.** Preserve stored mode, history, attachments, proposals, session markers and old homes without migration or deletion. Continuing, retrying, resuming or branching a Codex/Claude scoped conversation fails with `execution_mode_unsupported`; history remains viewable/exportable. Starting a new native conversation is an explicit owner action, using the ordinary new-conversation flow; do not automatically import its old session or replay its history. Switching the provider or preset inside the old conversation cannot bypass this rule. Local scoped continuations remain supported.
4. **Resolve missing legacy modes conservatively.** For an existing conversation without an explicit root mode, use an explicit persisted turn mode only if unambiguous across the conversation and consistent with its recorded provider context. For historical Codex/Claude conversations or indeterminate provider provenance, absence of that persisted mode evidence refuses with `execution_mode_unsupported`. Preserve existing unambiguous resolution for providers that had only one supported mode: historical Local remains scoped, and historical Gemini/DeepSeek remain native. The currently selected backend cannot erase a recorded Codex/Claude origin. The service's current `mode` is mutable, so it cannot prove that an old conversation was native: changing a service from scoped to native, deleting its mode or changing the selected backend must never authorize a retired cloud continuation. Conflicting or indeterminate evidence also refuses. Use the same resolution in display and dispatch; an unknown historical mode is shown as unavailable, not relabeled native. New conversations without a requested mode default to native for Codex/Claude, regardless of the ignored old service `mode` setting; Local still defaults to scoped. Do not mutate stored rows to implement either behavior.
5. **UI behavior.** Remove the isolation toggle for new Codex/Claude conversations and remove the hard-coded fallback that advertises scoped when capabilities are missing. Missing capabilities disable sending until refreshed. An unsent saved scoped draft remains visible with Send disabled and a message to start a new native conversation; do not normalize and submit it silently. Old scoped conversations retain an accurate historical label and show: "Isolated Codex and Claude conversations are no longer supported. Start a new native conversation to continue." Use the existing New conversation action; do not add an automatic conversion control. Local retains its required-isolation indicator. Permission presets remain a separate control.
6. **Credentials and retirement order.** Do not copy credentials from the real CLI home, export a keychain credential, mount a real home into the old sandbox, or fall back to a 0.15 home. No cloud-scoped runtime is retained behind a flag. #45 may stop supplying `auth_file` without waiting for a replacement cloud sandbox. Coordinate the admission guard with #45 before its release so a stale route cannot fail late on a missing credential field. Finish UI/capability cleanup in W14 after #45 and #46 (the old-home retirement); leave old files on disk untouched.
7. **Native behavior remains the facade's responsibility.** #44 owns untrusted-project and project-MCP gating; #45 owns real-home discovery (including environment overrides), scheduled/native parity, hooks and permission presets. #34 must not reinstate a hooks grant or connector allow list. KeepHarness does not promise filesystem isolation for arbitrary external MCP servers or plugins merely because a CLI preset is read-only. Local's existing filesystem and effect boundaries are not relaxed by this decision.

### JEV result

On 2026-10-08, `master-jev-hook.request_decision` compared A (retire cloud scoped; reject legacy execution without fallback; preserve Local), B (copy only real-home file credentials into today's filtered sandbox) and C (rebuild isolation around real homes and full orchestration now). Criterion: D-038/D-039 parity, no surprise permission widening or login copies, smallest reversible 1.0 scope. Risk: medium, for a documentary implementation decision. Result: **A, confidence 0.99**, accepted above the 0.80 threshold. This is decision support, not evidence of runtime safety.

## Rationale

The existing cloud sandbox deliberately substitutes its own orchestration, so retaining it would require an exception to D-038 or a substantial redesign. Mounting the real home can expose credentials and permit CLI state writes; copying it creates drift and refresh conflicts. Removing an optional transport is smaller and reversible, provided old requests fail rather than silently gain native behavior. The provider's native modes already serve the 1.0 permission controls.

## Alternatives

- **A — retire cloud scoped for 1.0 (chosen).** Gives up staged cloud edits and the extra bubblewrap boundary; preserves the facade and removes credential copies. Users explicitly start native conversations.
- **B — keep scoped with real-home credential snapshots.** Rejected: still filters global/project orchestration, needs credential refresh and keychain policy, and preserves two configurations. Labeling it as an exception would not satisfy the current governing decision.
- **C — rebuild a facade-compatible cloud sandbox now.** Deferred: plugin subprocesses, MCP sockets, hooks, shared skills, writable session state and credentials need an independently tested boundary. Binding the whole home is not an accepted shortcut.
- **Keep the old route hidden behind a flag.** Rejected for 1.0: dormant dispatch and credential fallbacks would remain reachable and still need a support contract.

## Impact

Two W14 PRs are sufficient: first the admission/dispatch retirement with regression tests, then UI/history guidance and capability cleanup. The first PR's guard is a release dependency of #45 even though cloud isolation itself remains the last optional milestone item. This ordering prevents an intermediate release with a broken credential-copy route.

Required regression coverage uses fake homes with sentinel credentials and asserts zero reads/copies for rejected cloud-scoped runs; explicit requests, legacy roots, retries, branches, queued work, schedules and workflow stages cannot spawn a CLI. Native preset/trust tests still pass, Local's required isolation still fails closed when unavailable, and history remains readable. Browser fixtures cover the removed toggle, stale draft, unsupported historical conversation, New conversation action and Local indicator. These are implementation acceptance criteria, not claims that this documents-only change executed those tests.
