# KeepHarness 1.0 delivery plan

Status: proposed delivery contract. Baseline: `b773026`, 2026-10-08. This plan
defines future acceptance; it does not claim that 1.0 gates pass today.

## Definition of done

KeepHarness 1.0 is built, installed on the target host and visibly usable for
ordinary work with Codex, Claude Code and DeepSeek. Release requires:

- one owner and a provider facade whose source of truth is each CLI's login,
  trust, project MCP approval and supported plugin/app/MCP/skill state;
- native Codex and Claude runs on their real CLI homes; DeepSeek as a first-class
  provider on its isolated Codex engine, with no credential, state or session
  crossing into the owner's Codex;
- fail-closed retirement of cloud-scoped Codex/Claude, readable old history and
  unchanged Local scoped isolation;
- a complete Plugins flow: discover, inspect, explicitly install, then manage
  provider-specific state at a clear project and supported write scope;
- complete daily desktop paths for conversation, attachments, approvals, activity,
  files, post-turn edit review, commands, Settings and shortcuts;
- English and pt-BR UI under #16 after its design is approved; provider prompts
  and model replies remain independent of UI locale; and
- preservation of KeepHarness-only capabilities listed in
  [D-021](../decisions/d-021-keep-keepharness-only-features.md), including routing,
  Agents, workflows, Runs, Attention, Space, schedules, hand-off, quota meters,
  catalogs, Connection/MCP, backup/restore and eight palettes.

All waves below and #16 block 1.0 except #51. The P2 list is post-1.0.

## Release journeys

| Journey | Observable acceptance |
| --- | --- |
| Install and open | An AI installer conducts CP-01..CP-08 from the [installation specification](../installation-agent-spec.md) with individual commands; `install.sh`, `setup.sh` and `keepharness-install` are not substitutes. A wheel installed outside the checkout starts the chosen host service and opens the installed UI at the tested revision/state/ports. |
| Prepare providers | Codex, Claude and DeepSeek have distinct, truthful login/version/account/resource status. Unavailable providers explain the blocker and never silently fall back. |
| Ordinary turn | In an authorized synthetic project, choose provider/model/effort/access, attach a file, send, handle approval, receive and inspect the result, reload, continue, then use the explicit provider carry-over. Run visibly for all three providers. |
| Edit review | A completed editing turn names only its own edits and opens a bounded, read-only Changes view for add/modify/delete/rename plus truthful binary, large, missing and unavailable states. |
| Provider resources | From rail, Settings or composer, browse/search/detail/install, then switch a supported plugin/app/MCP/skill at the shown project/scope. A stale fingerprint reloads without overwriting external changes. |
| Find controls | Global search finds commands, settings and conversations; Settings search opens the exact preference; a searchable shortcut reference matches effective platform bindings and preserves focus/draft state. |
| Locale | English/pt-BR switching covers first-party text and accessibility labels, persists across restart and passes catalog-key/placeholder parity with deterministic English fallback. |

Automated tests use fake homes, keyrings and local endpoints, never the owner's real
CLI state. The final authorized host pass may use already configured CLIs without
reading or recording secret values.

## Final release checklist

1. All blocking issues close with merged evidence; #51 may remain open. No literal
   placeholder or unexplained required failure remains.
2. `pyproject.toml`, `agent_service/VERSION`, `desktop/package.json`,
   `desktop/package-lock.json` and every static UI/version label say `1.0.0`.
   Create `dossier/releases/v1.0.0.md` with behavior, acceptance, migration,
   limits and actual commands/revisions/results. Keep README and README.pt-BR
   headings and order synchronized when instructions change.
3. Full Python and `scripts/test-ui.sh` suites, layout lint, desktop policy/unit,
   conventions and complete operator suite pass. Every skip/known defect is named
   and shown not to violate this plan.
4. A clean tree builds wheel and sdist. The AI installer executes CP-01..CP-08,
   installs the wheel outside the checkout, runs `python -m control.install_check`,
   proves imports use the artifact and tests the final host start/stop/open path.
5. The installed host build passes light/dark and English/pt-BR visible journeys:
   installation/opening; ordinary Codex, Claude and DeepSeek turns; provider
   resources; command/Settings/shortcut discovery; and post-turn edit review.
6. A separate upgrade pass proves old homes untouched, old scoped history readable,
   unsupported work fail-closed, real-home login/state and accurate recovery notes.
7. Tag/publish only the exact passing revision and artifacts; publication remains
   a separate authorized action.
