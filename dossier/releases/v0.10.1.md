# Version 0.10.1 — Chat home fidelity and guided product tour

## Behavior

The chat remains the home screen. A compact top bar, state-grouped conversation
sidebar, inline Maestro plan, labeled composer, Files/Activity pane and permanent
status strip follow the approved Chat + Run console layout. Existing projects,
approvals, slash resources, provider controls and mediated publication remain
reachable. Provider quota meters display observed remaining allowance only; Settings → Provider usage preserves detailed guidance when a provider has no percentage. Search covers observed runs, the current plan and authorized project files. The Files view shows registered roots and observed Git status, with the existing server-folder browser still available.

The Run console opens beneath the chat, with Pipeline, Timeline, Logs, Runs and
Agents tabs. Pipeline follows the latest run in the selected conversation.
Unsupported run actions are disabled with an explanation. Sensitive span content
remains opt-in through Show content; publication enforcement labels stay explicit.

Generated Maestro plans now wait at a real human gate before running any step.
The existing enrolled browser session and owner checks authorize approval. An
edited plan is validated against the current project/model/effort policy and
recorded atomically with the approval; derived invocation metadata is rebuilt
from the final steps. Denial, expiry or cancellation runs no plan steps. Explicit
resource chains submitted by the user keep their existing execution contract.

A local, dependency-free guided tour starts on the first browser visit. About →
Take the tour replays it. Coach marks describe the visible areas, skip missing
targets and open the console for its steps. Keyboard navigation, focus containment,
reduced motion and a bottom-docked card on narrow screens are supported.

## Acceptance criteria

- At 1440 × 900, the regions, hierarchy, chips, status strip and console header
  match the approved layout; at 400 × 812 there is no page horizontal scrolling.
- All six existing themes retain readable controls and semantic state labels.
- Empty model configuration uses an inline notice and preserves the chat shell.
- The status strip resolves activity polling and reflects real run counts.
- Pipeline selects the current conversation's latest run without manual selection.
- Tour Next, Back, Skip, arrow keys, Escape and About replay work; absent targets
  are skipped and unavailable browser storage never prevents normal use.
- Existing functionality and permission boundaries remain intact.

## Migration

No database or configuration migration is required. The tour stores only its seen
flag (`tail-harness-tour-seen`) in browser localStorage, guarded against storage
errors. Release identifiers and the packaged tour assets are updated together.
Generated Maestro work now requires plan approval, including work submitted by
an API client. The existing approval timeout and restart invalidation rules apply;
there is no automatic approval fallback.
