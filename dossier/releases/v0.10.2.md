# Version 0.10.2 — Workspace sections and extensive visual QA

## Behavior

The chat retains the approved mock-4 regions and the T7 baseline interface scale
(`774f464`). Both sidebars remain resizable and collapsible. Long labels truncate
with tooltips, and overflowing content scrolls inside its own region.

The right pane stacks Files, Background tasks, Resources and Activity. Section
headers expose counts, collapse controls and adjustable content sizes. Background
tasks reuse the activity endpoint; project resources reuse the slash palette's
resource catalog and preserve source labels.

The Run console opens with a useful desktop height, remembers manual resizing,
offers a visible keyboard-operable resize handle and supports maximize/restore.
Its desktop height leaves the composer reachable; on phones it becomes a sheet.
Storage errors must not interrupt these interactions.

## Acceptance criteria

- The T7 baseline font sizes, row heights and spacing are preserved at 100%
  browser zoom across all six themes; no global scale reduction is introduced.
- At 1280 × 720, the composer and a complete pipeline step with its actions remain
  visible when the console opens; panels scroll internally without page overflow.
- Width, console height and section preferences survive browser reloads.
- Keyboard resizing, visible focus, readable contrast and controls of at least
  24 × 24 px remain available.
- Visual QA captures four viewport sizes (1440 × 900, 1280 × 720, 1024 × 768 and
  400 × 812), six themes and six states (console closed/open, tour, plan,
  publish gate and slash palette): 144 combinations.
- Visibility checks use bounding rectangles and hit testing to detect clipped or
  covered controls, alongside overflow, title and pipeline completeness checks.

## Density decision

On 2026-10-01, the owner clarified that the earlier density feedback came from
viewing the app at 120% browser zoom. At 100%, the T7 baseline size is optimal.
This supersedes the original compact-density request: global font, row and padding
reductions were reverted. The release preserves baseline scale while improving
console visibility, workspace organization and overlap handling.

With the same synthetic conversation at 1440 × 900, before/after measurements
confirm unchanged top bar (48 px), sidebars (300/390 px), conversation row
(65.45 px) and chat width (750 px). Console height increases from 330 to 405 px,
and its usable content area from 285 to 353 px. At 1280 × 720, the default is
340 px so the visible resize handle does not reduce the original usable area.
The default is approximately 45% of the viewport, with a 340 px desktop minimum
subject to available space; maximizing and resizing preserve the composer.

## Migration

No database or server configuration migration is required. Browser layout
preferences are stored locally with guarded storage access. Existing approvals,
publication permissions and provider operations retain their contracts.
Release identifiers, Gemini client information and both README files advance
together to 0.10.2. Private mock/reference assets are not packaged or committed.

The browser suite accepts `TH_ADMIN_PORT` and `TH_CHAT_PORT` overrides so concurrent
worktrees can validate against separate temporary servers. Defaults remain 18094
and 18095; test state is still created and removed in a temporary directory.
Occupied or repeated ports are rejected, and every run checks the served API
version and HTML release label against the local VERSION file before testing.

## Validation

- Full Python suite: **1,433 passed, 37 skipped, 12 subtests passed** (103 warnings).
- Targeted visual suite: **144/144 screenshots and 15/15 profile scenarios passed**.
  Each viewport/theme/state combination checks horizontal page overflow, visible
  controls by bounding rectangles and hit testing, 24 px targets and contained
  labels. The six themes also receive text-contrast checks in all six states at
  1440 × 900. These checks do not replace a complete accessibility audit.
- Baseline scale guards verify 15 px root text, a 48 px top bar, 300/390 px
  sidebars and the original approximately 65.45 px conversation row.
- Full browser run 1: **99/99 files passed**, zero failures; served version 0.10.2 verified.
- Full browser run 2: **99/99 files passed**, zero failures; served version 0.10.2 verified.
- Naming/language/README parity: **0 errors, 0 warnings, 0 Portuguese hits**;
  exact bilingual heading text and order also match.
- Independent frontend, test-artifact and release-document reviews completed with
  no outstanding findings. The native popover synchronization correction passed
  **10/10** focused repetitions before the second successful full browser run.

Both successful browser runs enumerated every root and persona spec, including
all 144 visual states and 15 profile scenarios. They used temporary state and
free ports 18494/18495. The runner checked API and HTML release identifiers before
each run. Diagnostic runs found the outdated exclusive-pane assertions and the
native popover test race documented below; those failed runs are not counted as
successful validation.

The seven simulated profiles cover a beginner opening/dismissing the console,
a rushed user maximizing/restoring without losing a draft, a professional using
long names and saved sections, keyboard resizing and recovery, mobile rotation
and empty folders, an engineer checking resources/activity/persisted bounds, and
a UI specialist opening/dismissing the slash palette. Each profile has a main
and recovery scenario, plus one mobile empty-state scenario. These are automated
simulations, not research with human participants.

The visual campaign reproduced and fixed small activity/Peek targets, palette
occlusion, tablet pane and pipeline-action overlap, publication evidence covering
approval buttons, and console height drift during initial rendering. Existing
assertions changed only for the requested mobile sheet, stacked pane visibility
and additional resource requests. Response-format and screen-reader fixtures now
use the global pane toggle when they need to hide the entire workspace. Original sidebar-width expectations were
restored when the owner canceled global down-scaling. The new profile tests use
actual Maximize/Restore activations, keyboard increments within available bounds,
and the visible Stop control while a run is active. A later full-run timing
failure in the project-folder menu was corrected only in the test: it now waits
for native popover closure and the queued ARIA update before the same strict
assertion. Ten sequential focused reruns passed; the frontend was unchanged.

At 1440 × 900 and 1280 × 720, the first complete step, action controls and
composer fit initially without console scrolling. At 1024 × 768, the restored
baseline scale requires internal console scrolling between the action row and
the complete step card; there is no page overflow or pane overlap. On phones,
the full-height sheet keeps its tab strip horizontally scrollable.

Screenshots and JSON summaries are generated in unique temporary directories;
no private mock or reference assets and no environment-specific pixel baselines
are committed. The visual README documents reproduction and separate comparison
capture. The private comparison captures are `compact-desktop-app-closed.png`,
`compact-desktop-app-open.png`, `compact-desktop-mock-closed.png` and
`compact-desktop-mock-open.png`. Additional `compact-desktop-*`, `compact-720p-*`
and `compact-mobile-*` images record the other important states.

Remaining differences from the mock are intentional or content-dependent: the
right pane has four stacked sections instead of two exclusive tabs; the console
is taller; real provider availability and fixture history differ; retained
project/server-folder controls add content; publication evidence and narrow
console content scroll internally. Unsupported Re-run, Fork and export actions
remain disabled with explanations. Comparison is visual and geometry-based, not
a claim of pixel-identical rendering.

The tour-seen marker retains its existing content epoch, so upgrading does not
force an unchanged introductory tour on returning users.

Agent token/cost totals are unavailable; no efficiency comparison is claimed.
