# Version 0.12.0 — Catalog provisioning, private credentials and concurrent providers

## Behavior and acceptance

Trusted catalogs may provide an optional `harness.catalog.json` declaring resources,
context/rules, Python dependencies, consumer cwd, allowed hooks, integration
contracts, preflight checks and writable state. Existing discovery remains the
fallback. The palette explains missing prerequisites without provisioning or
returning credential values. Provisioning is an explicit local owner action and
requires the managed harness to be stopped: shared environments must not change
beneath a running provider. Maintenance entries disappear only when the manifest
covers provisioning and its checks pass.

Runtime Python environments and writable memory/report folders live under the
control state's `catalog_runtime/<catalog_id>/`, separate from executable catalog
revisions. Dependency preflight compares the requirements digest with the last
successful explicit installation. Declared hooks are executable native pre-run
scripts, intersected with the project's hooks grant; unrelated/global hooks are
not enabled. Hook subprocesses have time/output bounds, redacted events and
process-group cleanup. Pins suppress all catalog hooks.

Projects can pin a trusted Git catalog to a detached worktree beneath the private
state directory. Write bits are removed, Git hooks are disabled during preparation,
and modified checkouts fail validation. **Preview update** fetches and shows
changed revisions across tracked files, including manifest resources and runtime
dependencies. **Move pin** consumes an expiring preview bound to the project,
catalog, prior pin and exact target commit. Old trees remain retained. Catalog
update commands are unavailable under pin; dispatch disables catalog/provider
hooks and supplies immutable-catalog instructions. Each invoked catalog records
`catalog_commit`, `catalog_dirty` and pin status in run events/resources. This
neutralizes the harness-managed update paths; unrestricted same-user commands can
still change permission bits, so native pins are not an OS isolation boundary.

The local **Catalogs and vault** panel shows prerequisites, current/proposed pins,
resource diffs and a pure drift comparison of matching `resource_id` values across
projects. Discovery covers Codex, Claude and Gemini formats. Drift includes
resource/dependency revisions and catalog commits; it never changes a pin.

The vault atomically stores integration bindings at mode 0600. Admin fields are
write-only and clear after submission; status and settings export contain binding
and field names, never values. Contracts declare consumers, environment mapping,
precedence, nonsecret endpoint configuration and mediation. Project/catalog scope
is checked at dispatch and by the effect executor. Manifest contracts are reused
without silently narrowing their consumers or changing mediation. Credential
rotation increments a revision so affected running work loses the old grant.

Advisory contracts inject credentials into execution-local native subprocess
environments. Mediated contracts never inject their secrets; the supported Jira
publication retains the P3 immutable single-use human approval/executor contract.
Fake subprocess tests cover independent concurrent environments and redaction of
complete, short and split credential values in harness-owned output surfaces.
The [adaptation guide](../../docs/integration-credentials.md#adapting-scripts-with-embedded-credentials)
describes replacing scripts' embedded credentials in generic terms.

Write ownership precedes dispatch. Leases cover overlapping writable roots,
mutable catalog cwd/state, and project-scoped work-item references across
conversations/providers. Competing writers remain queued with a clear reason.
Each provider has a lane with capacity one by default; conversation turns remain
serial and the inference capacity guard still surrounds every Maestro planner
and step. Cancellation, failures and reconfiguration release leases/capacity.
Running work-item tags cannot change beneath their lease.

`control/product.py` is the source of the unchanged Tail Harness identity. Build
metadata, bootstrap, standalone MCP client, UI labels, environment prefix,
state/config paths, icon and theme defaults derive from it. Generated static
exceptions are documented. A synthetic identity is built and installed beside the
original in temporary directories, exercising independent commands, MCP names,
state and branding. Lineage markers reject another identity's state; only the
historical slug and lineage can adopt unmarked upstream state. Owner enrollment
checks both control and approval state. Local model validation protects the
**effective** private state directory, its ancestors, descendants and symlink
aliases. No product name, `sem-projeto` or Tailscale identifier is renamed.

## Configuration, APIs and migration

See the [catalog schema](../../docs/catalog-manifests.md),
[credential contracts](../../docs/integration-credentials.md) and
[identity generation](../../docs/product-identity.md) for examples and boundaries.
The existing local cookie, origin and administrative-header guard protects all
new owner operations. HTTP bearer credentials do not grant local administration.

- `GET /api/catalogs`: projects, catalogs, prerequisites, declared integration
  metadata and resource drift.
- `POST /api/catalog-pin`: project/catalog plus `action` `pin`, `preview`,
  `update` or `provision`. Pin/preview accept `ref`; update requires the returned
  `preview_token`. Existing pins cannot be silently moved through the pin action.
- `GET /api/vault`: configured field names, bindings and nonsecret contracts.
- `POST /api/vault`: `set` or `delete`; set accepts a binding, values and explicit
  project/catalog integration scope. New nonsecret contracts may be included;
  conflicting manifest contracts and false mediation claims fail before storage.

Existing catalogs, conversation history, workflows and P3 credential files remain
compatible. Catalog registration still uses owner-managed settings. Existing
settings/runtime files gain optional catalog pins, integration contracts/bindings
and vault revision fields. State gains a private identity marker; no schema rewrite
or directory rename is performed. Updating packaged browser assets is required.
The unchanged chat tour keeps its existing content revision; product version
labels and Gemini clientInfo are 0.12.0.

## Security self-review

Authors and reviewers were distinct. Direct artifact inspection and regressions
reproduced and corrected:

- Unsafe provisioning-stamp symlinks; symlink/nonregular stamp rejection and
  atomic replacement prevent redirected provisioning writes.
- Update diffs missing custom resource directories and dependencies; comparison
  now includes tracked files from both pinned revisions.
- Shared mutable catalog cwd not participating in write ownership; lease roots
  now include those paths before concurrent provider dispatch.
- Binding/contract changes and first-time vault activation ignored by hot reload;
  affected jobs are revoked and the effect/vault readers use current paths.
- Short and chunk-split secrets escaping sanitization, plus injected variables
  reintroducing a mediated credential name; redaction and final exclusions cover
  these paths, with synthetic subprocess evidence.
- Provider fairness and cancellation before a task started; dispatch recalculates
  owner order and cleanup releases task-owned leases without singleton state.
- Synthetic DeepSeek authentication stripped by a hard-coded prefix, inherited
  lineage adopting unmarked upstream state, and enrollment bypassing lineage;
  identity consumers and regressions cover all three.
- Generated icon references replacing an independently selected sprite ID;
  icon generation and installed-package assertions now preserve that choice.
- Admin provisioning racing a managed running harness, stale form control/focus,
  conflicting manifest contracts and advisory credentials labelled mediated;
  owner operations and UI constraints now preserve the actual runtime contract.
- Duplicate admin button IDs interfered with connector administration; new panel
  IDs are distinct and the browser regression checks whole-document uniqueness.
- An unavailable catalog endpoint returned an incomplete object during the seeded
  chaos test; response validation now preserves valid state and usable refresh
  controls. A browser regression covers the failed request and successful retry.

0600 and read-only bits do not isolate unrestricted native processes running as
the same OS user. Enforced mediation requires private credentials outside worker
mounts; native/same-user publication remains honestly labelled advisory. Literal
redaction cannot prevent intentional encoding by a process already entrusted with
a secret. Provider-owned native session files are outside harness redaction.
Ownership coordinates one harness process, not unrelated applications or a second
independent harness instance.

Scoped/local transports do not yet carry catalog cwd/Python/state or advisory
credential environments: these combinations fail closed with palette explanations.
Context/rule-only catalogs remain usable where the provider supports them. A
catalog's runtime is shared across its project pins; differing dependency digests
require explicit reprovisioning and cannot run as independent environments at once.
Provisioning requires the harness installation's pip. Pinned checkouts and state
are retained; automatic garbage collection is outside this release.
