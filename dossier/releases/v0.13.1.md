# Version 0.13.1 — Round-one approval, workflow and interface repairs

## Behavior

This release resolves the first gauntlet's 29 finding records (28 distinct issues).
Chat remains home; mock-4 hierarchy, the approved scale at 100% zoom, persisted
`sem-projeto` and Tailscale identifiers are preserved.

- Native browser enrollment preserves same-origin confirmation while rejecting
  cross-site or null-origin requests. Approval sessions are revalidated after
  request-body reads, so a revoked session cannot commit a delayed decision.
- Scoped effect enforcement checks both private credential stores. Literal secrets
  in object keys, values and tuples are sanitized. Atomic dispatch rejects an
  equivalent prepared effect after another becomes executing, unknown or done.
- Orchestration reserves eligible local-model roots across provider lanes; runtime
  root changes invalidate active leases. Configured non-Codex coordinators survive
  unrelated reloads, and real coordinator changes have accurate cancellation reasons.
- Option gates share the native approval expiration limit. Workflow v1 rejects
  unknown source fields, unsupported gate choices/multiselect and non-finite inputs.
  Accepted step-gate choices are approve, continue, skip and deny, with at least one
  continuing/skipping option. Retained server metadata follows a separate internal
  validation path. Rerun bounds use the current source revision before insertion.
- Repeated resource selections consume distinct token occurrences, preserving each
  argument segment. Markdown fence checks honor closing length, indentation and suffix.
- The slash palette keeps options and previews separately visible, including mobile;
  origin icons use the theme foreground. Narrow consoles keep full cards and readable
  plan headings. Keyboard focus and ARIA state follow panel/popover visibility and
  responsive changes. Workspace resize controls have nonoverlapping 24px hit regions. Default section
  scroll areas budget for those handles without creating a second outer scrollbar.
- The tour places explanations around their targets and restores visible focus after
  responsive changes. Drafts retain their text, resource selections and attachments
  within each conversation and the new-conversation project scope in the current tab.
- History distinguishes failed, cancelled, interrupted and completed outcomes. Plan
  cards retain approval decisions and terminal outcomes. Failed/interrupted/cancelled
  runs with a persisted workflow checkpoint offer Resume workflow, which calls the
  existing recovery endpoint. Unknown publication outcomes remain guarded by that API.

## Acceptance criteria

- Regression tests first reproduce the reported failures; visual regressions use
  browser geometry and hit testing, including mobile keyboard navigation.
- Concurrent publication and write ownership remain exclusive; approval authority,
  secret redaction and recovery restrictions retain their negative tests.
- Seven simulated profiles cover beginner, hurried, professional, accessibility,
  mobile, engineering and UI/UX scenarios; these are not studies with real users.
- Full pytest (including slow tests), two complete UI passes and conventions pass.
- Runtime/package/HTML/provider/tour identifiers are 0.13.1, and the English and
  Portuguese README heading structures match. Historical release notes remain intact.

## Migration

No database migration or identifier rename. New draft snapshots use per-conversation
and per-project new-conversation keys in browser sessionStorage; the existing
`remote-view` snapshot remains supported. Review workflow files that previously used
unsupported/unknown fields or arbitrary gate option IDs: they now fail admission
instead of entering a run that cannot continue. Existing valid declarations remain
compatible. The tour revision advances with the release.

gate; eleven responsive/accessibility checks and six draft/recovery journeys.

production changes, push or merge is part of this round.

identifiers equal 0.13.1 and README heading lists match exactly.
