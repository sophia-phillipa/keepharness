# 0.14.0 — Codex-style shell, your agents and the aggregator

## Behavior

The harness adopts the layout of the ChatGPT/Codex desktop app while keeping every Tail Harness capability, and turns the aggregator into something visible and usable.

- **Shell**: a 50 px icon rail (sidebar, search, attention, files and activity, runs and pipeline, agents and skills; quotas, admin, theme, about and settings at the bottom), a Chat/Code switch, the 640 px composer card with a sub-bar, Codex-like menus and the Graphite (dark) and Paper (light) default palettes; the six existing palettes stay selectable. The rail and sidebar head are Electron drag regions.
- **Projects and chats**: a project's conversations live only in its folder (folders start expanded, remember a collapse, offer a compose icon and "No conversations" when empty); every other conversation is listed under **Chats**, attention first.
- **Status dots**: one dot per conversation instead of status groups — yellow needs your answer, spinner running, ring queued, red failed, accent unread — and a summary dot on a collapsed folder.
- **Composer sub-bar** for a new conversation: Choose project, **Files** (files panel), **Agents** (`@` list) and **Plugins** (connectors and plugins installed, available for this project and route, used here in the last 30 days, with the approval or isolation note). A file selection offers **Attach to message** and **New chat with these files**.
- **Your agents**: create an agent with its own name, purpose, instructions, tasks, target output, provider, model and effort; call it with `@@name` on any provider. Choosing it moves the composer to its route; choosing another model or agent ends its conversation on the next send while the history carries over. Stored by the harness with atomic 0600 files and revisions.
- **Aggregator dividers**: the chat marks each model or provider change ("Model changed to …", "Switched to … · provider — the conversation so far goes with it").
- **Settings › System** shows the local admin (Providers with environment scan, Operations, Runs, Catalogs and vault) on the same screen; the admin hides its own navigation and follows the harness theme.
- **Model servers on your network**: add an OpenAI-compatible server (for example over Tailscale) in the local provider; it is probed, saved with an optional private key and its models join the local provider.
- **Claude login** in the admin accepts the code the browser shows when the callback cannot reach this machine.

## Acceptance criteria

1. Sidebar: project chats appear only in their folder, other chats under Chats; each state shows its dot with an accessible name; folders remember collapse.
2. Composer: Files opens the panel; Agents inserts `@` and lists agents, yours first; Plugins lists available, unavailable (with reason) and recent usage for the chosen project, model, execution mode and access mode, never exposing commands, URLs with credentials, environment or headers.
3. Agents: create, edit (with revision) and delete; `@@name` resolves only for a selected agent of yours; the composer adopts the agent's route; a model or agent switch releases the persona and keeps history; agents work on models without the read permission.
4. Settings › System: the admin may be framed only by the harness's own 127.0.0.1/localhost origin; the harness frames only the local admin; the iframe is created on first use; the group is hidden when the harness is opened over the network.
5. Network model servers: address normalization, probe without proxies or redirects, size and time limits, key file 0600 written atomically and never in settings, audit or responses; unreachable servers are skipped.
6. Full Python and full UI suites pass on the final source state with coordinated version identifiers.

## Migration

No database migration. New files under the admin state: `tail-agents/` (one JSON per agent) and private keys for network model servers; `settings.json` may gain `remote_models`. The admin's CSP now allows framing by the harness origin only. Upgrade all runtime and fixture version identifiers together to 0.14.0; the onboarding tour becomes eligible again. Persisted `sem-projeto` and Tailscale identifiers remain unchanged.

## Actual validation

- Full pytest on the integrated branch before the version bump: **2521 passed, 37 skipped** (the two environment tests that need a writable virtual environment and the product build backend were deselected; they fail the same way on main).
- Full UI campaign on the integrated branch before the version bump: **126 files passed, zero failed**. An earlier campaign had one load-dependent failure (round 8 A5-F3) that passed twice in isolation.
- Real provider checks with Codex: model switch with context kept (code word recalled); a user agent on GPT-5.6 Sol answered with its marker, a switch to GPT-6 Astra kept the context, and calling the agent again restored its route. The connectors and plugins panel listed the real Codex inventory (7 connectors, 10 plugins).
- Not validated live: Claude and DeepSeek routes (Claude not logged in, no DeepSeek key), a real tailnet model server, Electron packaging.
