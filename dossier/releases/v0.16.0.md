# 0.16.0 — Wave 3: whole attachments, project-bounded Automatic, Archive and folder-less projects

Status: In development — sections are added as each package merges to main.

## Behavior

Wave 3 of the 0.15.0 gauntlet follow-up (decisions D03, D11, D31, D33, D39, D40 and D41, accepted by Sophia on 2026-10-03). Each section below names the work package (WP) and the ledger or decision ids it answers; a package is listed once it is merged on the release branch.

### Attachments (WP-12)

- **Context limit after narrowing**: the 100,000-character limit applies to the context actually sent, after the pending-file narrowing, so a conversation of about 16 document-heavy turns no longer fails with `source_context_limit` and loses its native session (HAR-R3-6).
- **Claude reads the attachments folder**: Claude Code gets the attachments folder through `--add-dir`, so Ask mode no longer asks to read an internal path (HAR-R3-4). Codex already reads it through the reader.
- **Excerpt chip**: uploads, attach and history expose `excerpt: true` when only an excerpt of a long file is sent, and the UI shows an "excerpt sent" chip instead of a silent cut (`EXCERPT_CHARS`, `excerpt_metadata`).
- **Image notice once**: the "image ignored" notice is built only for files attached this turn or not yet noticed on the same backend, model and mode route, so it no longer repeats on every later answer (HAR-R1-7, `noticed_before`).
- **DOCX and XLSX text** (HAR-R3-7): `word_text()` walks each WordprocessingML part (document, headers, footers, footnotes and endnotes), joins runs without separators and ends paragraphs with a newline, so "R$ 1.250,00" is no longer split at formatting runs. XLSX shared strings are sent once; `xl/sharedStrings.xml` is no longer emitted as a page.
- **Text encodings** (HAR-R3-8): `decode_text()` honours UTF-16 and UTF-8 BOMs and falls back to Windows-1252 (Excel's pt-BR CSV default) unless the bytes hold control codes, so such files are no longer refused as binary.

### Access: project-bounded Automatic, Full access setting and offline schedules (WP-04b; D11, D03)

- **Automatic stays in the project**: Codex and DeepSeek run Automatic in a workspace-write sandbox with the project roots as writable roots, network from the internet grant, `approvalPolicy: on-request`, so anything beyond the project escalates to an approval card; host connectors ask before every call. Claude Code runs Automatic with `--permission-mode acceptEdits` inside the working directories, with ask rules for Bash and `mcp__*`. Gemini asks the owner before a shell command or connector (see Review fixes).
- **Full access is owner-only and off by default**: Full keeps `danger-full-access` / `bypassPermissions`, but only when the new admin setting `full_access` (default `false`) is on. Submitting Full otherwise answers 403 `full_access_disabled`, a queued Full run fails closed, and `GET /v1/models` reports `full_access` to the owner only. The admin dashboard gets an "Allow Full access" card that saves the setting at once; the access menu describes the bounded Automatic per provider, hides and disables Full access until the setting is on, and falls back to Ask for a restored or stale "full" choice.
- **Scheduled runs are offline by default**: a schedule gains `allow_internet` (default `false`; older files read as `false`). A scheduled run carries the internal `schedule_internet` marker and, unless the task opted in, its effective internet permission is forced off, which every adapter already enforces (Codex sandbox network and web search off, no Claude web tools, Gemini web tools denied, local sandbox offline). The Scheduled editor has an "Allow internet" checkbox, off by default.

### Archive, Delete permanently and storage (WP-11; D31, D33)

- **Archive replaces the old Delete**: Archive reuses the `deleted_conversations` table (same hide semantics, so older releases read it the same way) and adds Unarchive. `PATCH /v1/conversations/{id}` with `{"archived": bool}` archives or restores; `GET /v1/conversations?archived=true` lists the archived ones.
- **Delete permanently really deletes**: `DELETE /v1/conversations/{id}` now purges the conversation's jobs, events, gates, effects, title, approval rules, uploads no other turn attaches, session folders, Maestro plans, workspace answer copies and provider sessions in the harness-owned provider homes (never `~/.codex` or `~/.claude`). It archives first, removes the disk copies off the event loop, then drops the rows in one transaction, so an interrupted purge can simply run again. Every job route then answers 404. `purged-turns.jsonl` keeps ids, times, model and tokens only.
- **Live-only caps and dedupe**: identical uploads become hard links to the first kept copy with the same sha256; the 1000-run and 2 GiB caps count only live content, each hash once, checked after hashing. `GET /v1/storage?project_id=` reports runs and bytes against the caps and warns from 80%. The caps live in `agent_service/config.py` (`MAX_PROJECT_RUNS`, `MAX_PROJECT_UPLOAD_BYTES`, `STORAGE_WARNING_RATIO`). Spec: `docs/conversation-retention.md`.
- **UI**: the row menu has "Archive conversation" (one click) and "Delete permanently" (the existing dialog as its second, explicit step; the copy says what is erased and that it cannot be undone). Settings › Archived chats lists archived chats with Unarchive and Delete permanently and shows the Storage line, highlighted when the server warns; limit errors point to that screen.
- **Migration tool**: `python -m agent_service.storage_migration --state-dir <state> [--apply]` links identical existing uploads once (see Migration).

### Folder-less projects, Files picker and richer schedules (WP-17; D39, D40, D41)

- **Projects without a folder** (D39, OP-R1-19): `POST /v1/projects` accepts `"paths": []` and answers 201; the project is stored with `root` null and no additional roots, and a PATCH with an empty list detaches the folders and keeps the conversations. Name rules, uniqueness and protected-path checks are unchanged. `GET /v1/project-folder` answers 422 for such a project. The project dialog no longer requires a folder (0 to 20 folders; `docs/PROJECT-FOLDERS-20260919.md`).
- **Files chip picker** (D40, OP-R1-22, PRD-R2-8, QA-R2-2): the Files chip no longer flips a Chat into Code; it opens a popover with the recent uploads of this tab, the Space pages (attached with their current text), "Upload…" and, when the project has a folder, "Browse project files…". A page is attached into the composer's own project after its permissions are checked, never by switching project, which fixes the false error for a page from another project.
- **Schedules pick an agent and pages** (D41, PRD-R2-5): a schedule gains the optional fields `agent` (a KeepHarness agent name) and `page_ids` (up to 5 pages of the schedule's project). Saving applies the composer's marker rule (a stray `@@name` is refused with `schedule_agent_unselected`) and checks that the agent exists (`schedule_agent_missing`); a paused schedule can still be renamed after its agent is gone. A run uses the agent's current revision and appends each page's current text in a fence longer than any backtick run in the page; a missing page is a failed run with `schedule_page_missing`. The Scheduled editor has an Agent picker and Pages checkboxes.
- **Polish**: Run now keeps the editor's typed fields and takes the new revision (CDX-R1-4); empty Space and Scheduled panes show heading, text and a primary action (UX-R1-9); the Files section takes the free height of the side panel unless the user dragged it, the project folder tree shows at least eight rows and its chevrons are 24 px (UX-R1-6, UX-R4-2). New test ids: `files-chip`, `files-menu*`, `page-empty-new`, `schedule-empty-new`, `schedule-agent`, `schedule-pages`.

## Migration

- **No automatic data migration.** The database schema is unchanged; the archive flag reuses the existing `deleted_conversations` table, so a conversation hidden with 0.15.0 appears under Settings › Archived chats.
- **Delete now erases**: `DELETE /v1/conversations/{id}` used to hide a conversation and now purges it, with no way back. Clients that used it to hide must call `PATCH /v1/conversations/{id}` with `{"archived": true}` instead.
- **Reclaim space from old duplicates** (optional): `python -m agent_service.storage_migration --state-dir <state folder>` is a dry run by default: it opens the database read-only, writes nothing and prints, per project, the kept runs, the uploaded bytes counted against the cap, the archived conversations and the bytes linking would free. Add `--apply` to replace each duplicate with a hard link, only after both files hash to the recorded sha256; it logs every file to `storage-migration.jsonl` in the state folder, and reruns skip what already shares an inode. Rollback: linking never changes content; give a file its own copy again with `cp -p <source> <source>.copy && mv <source>.copy <source>` for each `linked` line of the log (also in the module header).
- **Automatic is narrower**: Automatic on Codex, DeepSeek and Claude Code no longer runs unrestricted; edits inside the project proceed, and anything else raises an approval card. Gemini asks before a shell command or connector.
- **Full access is off until you enable it**: turn on "Allow Full access" in the admin dashboard (setting `full_access`, default `false`). Until then a Full submit answers 403 `full_access_disabled`, and a restored "full" choice falls back to Ask.
- **Scheduled tasks are offline**: existing schedules read `allow_internet` as `false`; tick "Allow internet" on each task that needs the network. A Gemini scheduled task without it runs without connectors.
- **API changes for clients**: new `PATCH /v1/conversations/{id}` `{"archived": bool}` and `GET /v1/conversations?archived=true`; `DELETE /v1/conversations/{id}` purges (was a hide); new `GET /v1/storage?project_id=`; `POST /v1/projects` accepts `"paths": []` (201, `root` null) and `GET /v1/project-folder` answers 422 for such a project; `GET /v1/models` carries `full_access` for the owner; the submit routes can answer 403 `full_access_disabled`; schedules gain `allow_internet`, `agent` and `page_ids` and the codes `schedule_agent_unselected`, `schedule_agent_missing` and `schedule_page_missing`; attachment metadata gains `excerpt`.
- **No rollback script**: a purge cannot be undone and hard-linked uploads stay shared, so back up the state folder before deleting permanently or running `--apply`.
- **Browser**: the onboarding tour becomes eligible again once with the new version.

### WP-14: supervision, drain and backup (L22, L23, L24; D18, D32)

**Behavior**
- The admin watches the harness it started. After an unexpected exit it starts it again after 2 s, doubling up to 30 s. Three exits in a row, each within 60 s of the start, stop the restarts: `startup_error` says how many times and the last exit code. `status.last_exit` (`code`, `at`, `uptime_seconds`; negative code = signal) is returned by `/api/state` and written to `audit.jsonl` as `harness_exited:<code>`. A stop, a shutdown or a manual start never counts as a crash.
- On SIGTERM the admin waits up to 10 s for queued and running work before stopping the harness (inside the unit's `TimeoutStopSec=30`); work still running after that is recorded as interrupted by the harness, as before.
- The desktop app asks before closing the window when it started the admin itself and work is running, queued or not known to be idle ("Keep working" is the default). A service started by systemd or by someone else is left running when the window closes (D18).
- `keepharness backup [--output FILE] [--with-secrets]` writes an owner-only `.tar.gz` (manifest first, SQLite databases copied with the online backup API). Without `--with-secrets` it leaves out `*.key`, `*.pem`, `providers/`, `harness.secrets.json`, `local-sessions.json`, `approval_sessions.sqlite3`; it never includes `venv`, logs, locks or temporary files.
- `keepharness restore ARCHIVE` prints the plan; `--apply` restores. It refuses a state that is in use, a state that already holds data (unless `--replace`, which moves it to `<state>.before-restore-<time>`), an archive of another product identity, an unsafe archive, a database that does not match the manifest, and the default state while the Tail Harness folders still wait to move.

- Killing the harness with SIGKILL restarts it and records `last_exit.code == -9`; three quick crashes stop the restarts and report; delays are capped; a stop during the backoff cancels the restart.
- The admin shutdown polls `busy()` until it clears (or 10 s) and only then terminates the harness.
- A backup taken while a writer inserts restores exactly the counts in its manifest, with `integrity_check` ok; secrets are absent by default; restore refuses while the service answers.
- `policy.test.cjs`: no prompt when the app does not own the backend or it is idle; a prompt when busy or unknown.

**Limits**

- Conversation `mcp.json`, `harness.effect_credentials.json`, `.credentials.json`, `oauth_creds.json` and `.claude.json` count as secrets and need `--with-secrets`.

### WP-19 S2a: guest boundary fixes

#### Behavior
- **Serve proof.** Tailscale identity headers (`Tailscale-User-Login`) map a login to its tailnet client only when the connection that carries them was opened by tailscaled. The harness looks up the connecting socket in `/proc/net/tcp` (`control.local_access.served_by_tailscaled`): the client endpoint must be 127.0.0.1 and every row for that connection towards the harness port must be ESTABLISHED, owned by uid 0 and have a socket inode (after a client closes, the kernel shows the row as FIN_WAIT2 or TIME_WAIT with uid 0 and inode 0, which a local account could otherwise abuse by sending forged headers and closing). Uid 65534 is never accepted. The lookup is never cached. If the proof fails, or `/proc/net/tcp` is unreadable (another platform, no row), the headers are ignored, the request falls back to its other credentials (so usually 401), and the log says: `Tailscale identity headers ignored: the connection was not opened by tailscaled ...`. When tailscaled runs without root (userspace mode), tailnet logins are refused. Inside a user namespace (for example a rootless container, `/proc/self/uid_map` not `0 0 4294967295`) host uid 0 is unmapped and shows as 65534, so tailnet sign-in is off: the harness logs one line at startup, the admin status reports `tailnet_signin_off` ("Tailnet sign-in is off: KeepHarness runs inside a user namespace; run it on the host or use the VPN key"), and the refusal warning is limited to one line a minute.
- **Funnel refused.** A request carrying `Tailscale-Funnel-Request` gets `403 funnel_denied` from the harness before any credential is looked at, and the admin guard refuses it with its existing 403 whatever the Host says.
- **Guest project scope.** Clients other than `local` (the vpn key and every tailnet login) start with `sem-projeto` only. A hot reload now applies the same rule as startup: the owner gets every project, others only when `shared_projects` is on. Before, any reload appended every registered project to every client.
- **Host files are owner-only.** `GET /v1/project-files?view=tree` and `POST /v1/project-files/attach` with a system `root_id` answer `403 host_files_owner_only` for every client except `local`. Attaching from a project root (`project_root_id`) is unchanged.
- **RC-10.** The filesystem root (`system`) is no longer a root: `root_id=system` gives `system_root_denied`, the attach default is `home`, and `browse_system` refuses a requested folder that passes through a hidden or system component (for example `.ssh`, `lost+found`, or a symlink that resolves into them) with `path_not_authorized`. Navigating to a project whose folder is outside the home and media roots now answers `system_root_denied`.
- **`shared_projects` setting.** A top-level boolean in the admin settings (default `false`, explicit boolean, same pattern as `personal_setup` and `full_access`) is passed to the runtime config; when `true`, the VPN key and tailnet guests receive the projects. No panel switch yet (S2b); documented in `docs/local-owner-access.md`.
- New UI copy for `funnel_denied` and `host_files_owner_only`.

#### Acceptance criteria
- `tests/test_serve_proof.py`: a uid 0 row is served; another uid, no row, a non-loopback client, a mixed uid-0/user row set, a malformed, empty, binary or missing proc file are not; forged Serve headers from a user socket get 401 and a log line, and the same headers over a uid 0 socket map the login.
- Review fixes: `tests/test_serve_proof.py` (closed-connection rows with uid 0 and inode 0 are refused, 65534 never accepted, uid_map detection, startup log, log rate limit), `tests/test_control.py` (status message, validated setting), `tests/test_runtime_config_builders.py` (setting on and off). Real kernel check: after a user-owned client closes, the row is `05`, uid 0, inode 0 and `served_by_tailscaled` returns False while the server can still read the body.
- `tests/test_api_security.py::test_funnel_request_is_refused` (harness and admin) and `::test_guest_cannot_browse_or_attach_host_files`.
- `tests/test_shared_projects.py::test_guest_scope_survives_hot_reload`, `tests/test_runtime_config_builders.py::test_non_local_clients_start_with_sem_projeto`.
- `tests/test_authorized_file_tree.py::test_system_root_is_gone` and `::test_hidden_component_in_request_rejected`.
