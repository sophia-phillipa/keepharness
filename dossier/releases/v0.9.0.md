# 0.9.0 — Run console, live attention inbox and work-item references

## Behavior and contracts

Chat remains home. A status strip reports running, queued and human-waiting work
in the selected project. Clicking it or Ctrl/Command+J opens a collapsed-by-default
bottom console. Its keyboard-resizable desktop drawer becomes a full-screen phone
sheet. Pipeline selects current-conversation runs; Timeline shows a zoomable span
waterfall; Logs searches and filters loaded pages; Runs filters across conversations
and opens their chat; Agents reports provider/model running, queued and idle state
with observed quota when available. Each answer offers **View run**.

Span detail separates Metrics and Attributes from Input, Output and Prompt.
Content requires **Show content**, which explicitly requests the owner's content;
Hide content discards that browser projection. Rendering uses text nodes, including
provider content, tool requests and log payloads. Existing SSE feeds trigger
refreshes; a lightweight activity poll includes other conversations and reconnection.

Needs you contains only live, unexpired requests backed by an unresolved waiter.
Gates additionally require a durable pending record. Resolved, expired, invalidated,
restarted and cancelled requests leave the inbox. It displays approval details,
gate options, risk and evidence. Resolution reuses the P0/P1 approval endpoint and
requires the enrolled human session; local access and API tokens confer no approval
authority. Failed authority checks preserve choices and explain enrollment.

`jobs.work_item` is a nullable, project-scoped reference with an index on
`(project, work_item)`. A project or trusted project catalog can configure
`work_item_pattern` (for example `TASK-[0-9]{4}`). Matching uses canonical invocation
arguments, not arbitrary chat text. Project and invoked trusted-catalog patterns
are checked together; distinct matches are rejected as ambiguous, and invalid
patterns fail validation. An explicit submitted reference overrides extraction.
Manual tagging accepts a bounded key or null. Maestro execution steps and
continuation turns inherit references; turns may explicitly override or clear them. The same key associates runs across conversations only within its
project and authorized owner. References do not lock competing writers.

New object event payloads include `schema_version`, `execution_id`, `attempt`,
`parent_execution_id` and terminal `outcome` where known. Maestro emits explicit
terminal records for planning and every started step, including failures and
cancellation. Codex item IDs and Claude tool-use IDs become `tool_call_id`; Claude
retains `parent_tool_use_id` for nesting. Old event consumers and historical rows
remain valid, including null quota snapshots.

`events_to_spans(job, events)` is a pure read-time projection. It creates
`invoke_workflow`, `invoke_agent`, `plan`, `execute_tool`, `chat`, `harness.gate`
and `queue_wait` spans. Open spans retain `end_ts: null`. Replayed IDs are deduplicated,
attempts remain distinct, overlapping calls pair by ID, and inferred
boundaries carry `end_inferred` with an unknown outcome until an explicit own
terminal establishes it. The `gen_ai.*` mapping is a local
JSON schema aligned with development OTel conventions, not an OTLP exporter.
No spans table or telemetry dependency is added.

## HTTP interfaces

- `GET /v1/jobs/{job}/spans`: authenticated job-owner access, content hidden by
  default; `include_content=true` opts into separate content records. Responses
  are not cacheable.
- `GET /v1/activity`: authorized owner's activity across accessible projects, or
  `project_id` to narrow it. `work_item` requires `project_id`, preventing accidental
  cross-project association. Includes jobs, live requests, counts, queue reasons
  and per-provider/model state and observed quota.
- `PATCH /v1/jobs/{job}/work-item`: owner-authorized manual tagging with
  `{"work_item":"TASK-1234"}` or `{"work_item":null}`.
- `GET /v1/jobs/{job}/events?format=json&after=0&limit=200`: cursor pagination for
  Logs, retaining the existing SSE behavior without `format=json`. Searches in
  the browser apply to loaded pages; Load more events continues past 500 rows.

The local admin Runs panel shares the same projection over complete ordered event
history using its existing read-only database reader. This avoids introducing
admin-to-harness credential plumbing. Its legacy recent-event view stays bounded;
its spans are not truncated and omit content.

These profiles are deterministic simulations, not research with real users or
screen-reader certification. Golden span cases cover single backend, four-stage
Maestro, overlapping tools, repeated steps, failed step, cancellation, reconnect,
gate wait and legacy unknown outcomes.

## Migration and limitations

The schema migration adds one nullable jobs column and its project index; existing
jobs retain null references. No historical event rewrite is required. Owner checks,
`sem-projeto`, Tailscale identities and existing approval enrollment are preserved.
Provider usage/quota is shown only when reported. Activity reuses the existing
shared-account Codex cache with its timestamp and owner-observed Claude quota;
absent snapshots and other providers remain null. Activity never refreshes quota
through a provider call, and no quota is estimated.
Work-item locking, checkpoints and publication mediation belong to later phases.
